# План переключения режима расчета доходности

## Цель

Дать пользователю возможность выбирать между двумя способами отображения годовой доходности:

- XIRR с учетом дат денежных потоков;
- простой доходностью, линейно пересчитанной на год.

Текущее поведение должно сохраниться по умолчанию:

- сценарий `Продажа` показывает `доходность, год`;
- сценарии `Погашение` и `Оферта` показывают `доходность XIRR`.

## Согласованный UX

Показатель доходности в секции `Результаты` становится переключателем в обе стороны:

- `доходность XIRR` -> `доходность, год`;
- `доходность, год` -> `доходность XIRR`.

Текст показывает текущее состояние и одновременно является действием. Это не группа кнопок с активным элементом: у вариантов не должно быть отдельного визуального состояния `active`.

Такой же паттерн применяется к переключателям учета затрат:

- `с комиссией` <-> `без комиссии`;
- `с налогом` <-> `без налога`.

## Визуальный паттерн

Использовать ненавязчивые текстовые touch-кнопки:

- без рамки;
- без постоянной фоновой заливки;
- спокойный голубой цвет текста;
- тонкое постоянное подчеркивание с небольшим отступом от текста;
- `active`-feedback при нажатии, например легкий голубой фон или изменение оттенка;
- достаточная touch-зона, ориентиром является высота не менее 44 px;
- `focus-visible` оставить для клавиатурной навигации, но не использовать как основной mobile UX-сигнал.

Подчеркивание означает, что текущую подпись можно нажать для переключения, а не то, что один из двух вариантов визуально выбран в группе.

Для переключателя доходности и подсказки сохранить два независимых действия:

- нажатие на текст переключает показатель;
- нажатие на иконку `?` открывает описание текущего показателя.

## Техническая реализация

### Состояние страницы

Добавить на `CalculatorPage` состояние режима доходности, например:

```ts
type YieldMode = "xirr" | "annualized";
```

Состояние остается локальным состоянием React-компонента. Ручной `refetch` обновляет данные облигации и форму, но не вызывает `setYieldMode`, поэтому выбор пользователя сохраняется естественным образом.

Начальное значение должно зависеть от сценария выхода и повторять текущее поведение. При переключении сценария рекомендуется возвращать режим по умолчанию для нового сценария:

- `sale` -> `annualized`;
- `maturity` и `offer` -> `xirr`.

В обработчике смены сценария нужно явно вызвать `setYieldMode(getDefaultYieldMode(nextMode))`. В эффекте, который уже определяет `isNewBond`, режим нужно сбрасывать только при загрузке новой облигации. Если оферта исчезла после обновления MOEX и сценарий автоматически меняется на погашение, это также считается сменой сценария и должно вернуть режим по умолчанию для погашения.

При ручном обновлении данных MOEX выбранный режим сохраняется автоматически: обработчик обновления не изменяет это состояние. Для этого не нужны `localStorage`, отдельные ключи сохранения или синхронизация режима с данными MOEX.

### Представление результатов

Изменить `createCalculationView` и `createSummaryRows`, чтобы выбор показателя зависел от `yieldMode`, а не напрямую от `CalculatorMode`.

Использовать уже существующие значения из `calculateBondTrade`:

- `annualizedXirrPercent` для XIRR;
- `annualizedReturnPercent` для простой годовой доходности.

Доменный расчет в `src/shared/domain/bondTradeCalculator.ts` менять не требуется, поскольку оба показателя уже рассчитываются и возвращаются результатом.

### Переиспользуемый UI

Расширить модель строки результата и/или `ResultRow`, чтобы подпись могла быть текстовой кнопкой с обработчиком переключения.

Для переключателей комиссии и налога вынести общие классы/вариант в переиспользуемый UI-паттерн, а не дублировать длинные классы в `CalculatorPage.tsx`.

Технически элементы должны оставаться `button` с корректной клавиатурной доступностью. Для скринридеров добавить описания действия, например:

- `Переключить на доходность, год`;
- `Переключить на доходность XIRR`;
- `Переключить на расчет без комиссии`;
- `Переключить на расчет с комиссией`.

Иконка подсказки текущего показателя должна иметь описание именно текущей формулы.

## Критерии приемки

- При первом открытии калькулятора поведение показателя не отличается от текущего.
- Пользователь может переключать показатель кликом по его названию в обе стороны.
- Подпись, tooltip и отображаемое числовое значение всегда соответствуют одному режиму.
- Переключатели комиссии и налога используют тот же визуальный паттерн, что и доходность.
- На мобильном экране элементы удобно нажимать пальцем.
- В интерфейсе нет рамок и тяжелых segmented-control блоков вокруг этих переключателей.
- Клавиатурная навигация и доступные имена действий не ухудшены.
- Существующие расчеты, сценарии выхода и детализация не регрессируют.
